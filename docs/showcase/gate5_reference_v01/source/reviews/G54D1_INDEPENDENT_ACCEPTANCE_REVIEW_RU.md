## 3. Прежний блокер исправлен по существу

В G54D обработчик `status_not_active` сохранял отзыв и корректно останавливал использование источника, но завершал отказ без требуемого настоящего решения местного Root.

Теперь узкая ветка:

1. Сохраняет аутентифицированное терминальное состояние источника.
2. Проверяет сохранённые pointer и STATUS относительно зафиксированных времён наблюдения.
3. Связывает исходный запрос, причину отказа, владельца и ревизию источника, source-review, подготовленный FETCH, STATUS и хеш свидетельств.
4. Получает новое фактическое решение местного Root `BLOCKED_FAIL_CLOSED`.
5. Ссылается на это решение в завершённом отказе.

В обоих событиях сценария `revoked_source` — EXACT и SHIFT — присутствуют реальные наблюдаемые вызовы и отдельные решения Root. Ранее полученные metadata-решения ACCEPT не переименованы в отказ. Терминальное состояние сохранено; нового бронирования и изменения реестра нет.

Старое время проверки используется для доказательства причины отказа, а не для продления разрешения на использование источника. Неизвестные ошибки не превращены в универсальный REFUSED. В потенциально неопределённом исходе подтверждения сохранено различие между отказом и `CURRENT_STATUS_UNKNOWN`.

Это устраняет именно обнаруженный дефект. Проверенные два события не выдаются за испытание гонки отзыва во время подтверждения или за проверку аварии после эффекта.

Источники: `candidate_domain/run.py` в финальном кандидате; `evidence/refusal_binding_d1.json`; `SUPERVISOR_EVIDENCE/p7_candidate_7071661f/`.

## 8. Почему это ещё не полное закрытие Gate 5

Различие установлено исходным планом и решением куратора, а не вводится после успеха.

| Рубеж | Текущее состояние |
| --- | --- |
| G54D1: согласованная коррекция, полная конечная native-матрица, live и две supplied-проверки | Принят этим независимым обзором |
| G55: общая матрица сокращённого Gate 5, объединение External DRS и нового домена, остатки прежнего scope, финальные source/release bindings и engineering admission | Требует отдельного завершения |
| R19: внесение принятого исходного результата в owner, обычный R1 commit/push/readback | Не выполнялось в G54D1 |
| G56 / R20: финальная презентация, техническое приложение, полный Reader и пригодный к использованию kit | Ещё предстоит подготовить для принятого финального результата |
| R21: публикация финального комплекта и проверка ссылок/байтов при сохранении прежних материалов | Ещё предстоит |

Master V02 §18 определяет G5-5 и G5-6 именно так. §21.1 допускает `G5_REFERENCE_CLOSED` после обязательных R01–R22; до публикации возможен отдельный `ENGINEERING_ACCEPTED`, которому ещё предшествует завершение G55. Решение куратора §3.9 прямо сохраняет общую матрицу, source admission, owner landing и публикацию после успешной коррекции.

Сам возврат согласуется с этим: `FINAL_RESULT.json` содержит `gate5_closed: false`, `owner_landing: false`, `commit: false`, `push: false`.

Ранее опубликованная историческая презентация G54B1 остаётся правильной историей первого опыта. Она не заменяет публикацию принятого финального Gate 5.

Оставшиеся действия конечны. Этот обзор не назначает новую разработку, третий холодный запуск, отдельный action service или дополнительный авторский цикл. Полная защита от враждебного Python, широкая программа аварий/гонок, model-swap/conformance Gate 6, полная Factory/Cognitive Radiolaria и глобальная федерация не объявляются выполненными и не добавляются здесь в условия G54D1.

## 9. Формулировка для куратора и подготовки презентации

> Внешний модельный автор создал новый предметный процесс по публичному kit Radiolaria. Первоначальный опыт с тремя коррекциями остановился на неполной реализации требуемого отказа. После явного разрешения одной дополнительной коррекции сам автор устранил дефект. Неизменённый технический экзамен принял все 16 native-сценариев; три реальных модельных ответа потреблены программой; две независимые проверки сохранённых доказательств совпали без новых вызовов и эффектов. Успешный результат принят по расширенному протоколу, первоначальный INCOMPLETE сохранён. Дальше — общая приёмка Gate 5, внесение результата и финальная публикация.

Содержательный результат можно презентовать уже сейчас: переданное архитектурное знание позволило другому интеллекту создать работающий домен с внешним знанием, местными решениями Root, контролируемым изменением состояния и проверяемой историей. Точные границы опыта — четыре коррекции, восстановленное продолжение, конечный reviewed-reference профиль и учебный эффект — должны остаться видимыми.

**Итоговое решение по этому возврату: G54D1 принимается. Полное Gate 5 Reference closure фиксируется после оставшихся G55/G56, а не задним числом в этом архиве.**
