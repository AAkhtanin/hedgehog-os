## E. Exact finite strategy mathematics

The frozen numerical profile is `G4_REFERENCE_NUMERIC_V01`: `Q = 1,000,000,000`, equal exponents `αᵢ = 1`, and epsilon gain `ε = 1` fixed-point integer. The evaluator uses exact integer products and signed round-half-even (RHE). To compute RHE of `n/d`, it rounds `abs(n)/d` to nearest integer, resolves an exact half toward the even integer, then restores the sign. No floating-point ranking is used.

| Rule | Implemented expression | Scope |
|---|---|---|
| Weighted utility | `Uᵢ = RHE(Σⱼ wᵢⱼ xᵢⱼ / Q) − riskᵢ − latencyᵢ − coordinationᵢ` | Implemented here |
| Feasible set | `F = {s: every required hard predicate is known TRUE}` | Implemented here |
| Individual rationality | `IR = {s ∈ F: Uᵢ(s) ≥ Dᵢ for every context participant i}` | Implemented here |
| Strict dominance | `a` dominates `b` iff every `Uᵢ(a) ≥ Uᵢ(b)` and at least one is strictly greater | Implemented here |
| Pareto set | IR candidates without a strict dominator | Implemented here |
| Integer product | `score(s) = ∏ᵢ max(Uᵢ_fp(s) − Dᵢ_fp, 1)` | Implemented here |
| Ordering | Descending exact product, then stable candidate ID | Implemented here |
| Outcome/history update | Existing native proof, calibrated update and current history eligibility | Reused Gate 3 |
| Regret/stability, minimax/CVaR, sensitivity | Explicit `NOT_IMPLEMENTED`, with deferred reason | Deferred |

The implementation requires utility and disagreement values for every participant in the context. A `required_roots` subset does not silently remove another participant from IR or the product. The code first preserves exact term numerators, rounds the weighted sum once, and then subtracts the three penalties. Negative gains fail IR before epsilon is considered. Epsilon handles a zero gain; it cannot offset a loss.

Both native offers are feasible, IR and Pareto in both profiles. There is no invented third dominated native ticket. The utility table below displays `U_fp/Q`; the product displays the exact native integer divided by `Q³`. Display values never determine the ranking.

Equal utility vectors do not dominate each other. Scores are calculated for IR candidates; ranking is over Pareto candidates. A product tie uses stable ID ordering. If every IR candidate has zero gain for every participant, the explicit profile rule returns `NO_DEAL_ALL_ZERO_GAIN`. A recommendation can otherwise have weak IR, so strict improvement for every party is not promised.

| Condition | Result |
|---|---|

The strict contracts bound participants to 2–8, candidates to 1–32, and utility terms to at most 8 per participant/candidate. Utility features lie in `[−Q,Q]`, weights in `[0,Q]` and sum to Q; each penalty lies in `[0,Q]`; utility and disagreement lie in `[−4Q,Q]`. Product strings have at most 80 digits. Canonical inputs are bounded to 262,144 bytes, reports to 1,048,576 bytes; depth and node limits apply before expensive mathematics. Floats, bool-as-int, duplicate keys/IDs, unknown profiles, extra fields and cycles are refused.

The numerical fixture A/B/C/D illustrates dominance separately: A=(.9,.1,.5), B=(.5,.5,.5), C=(.4,.4,.4), D=(.95,−.1,.6), with zero disagreements. D fails IR; B dominates C; Pareto is {A,B}; products are .045 and .125 and B wins. This is **NUMERICAL_REFERENCE_NOT_RUNTIME**, covered by the recorded math test `test_strategy_fixed_sets_products_and_witness`.

This is a finite reference bargaining criterion. It is not a Nash equilibrium, strategic-regret calculation, truthfulness mechanism, universal optimum or fairness proof. The fixed scale, epsilon and profile are part of the identity; invariance under arbitrary changes of units is not claimed.

## F. Pressure, exact apportionment and a real budget

The five-feature profile uses a linear score:

`z_fp = RHE((4 × relevance_fp + 2 × lineage_fp − 2 × uncertainty_fp − cost_fp + raw_prior_fp) / 8)`.

Relevance, lineage, uncertainty and cost are in `[0,Q]`; the signed raw prior is in `[−Q,Q]`. The exact resulting range is `[−500,000,000, 875,000,000]`. The report retains each signed numerator and the single final rounding. The prior is applied once; an already adjusted G3 score is not added again.

| Feature | offer0 | offer1 | Interpretation |
|---|---:|---:|---|
| Relevance | .8 | .8 | Configured bounded inspection relevance |
| Lineage | .8 | .8 | Configured source-lineage quality |
| Uncertainty | .5 | .5 | Configured lack of certainty; not failure probability |
| Cost | .4 | .43 | Estimated normalized per-branch cost; not measured CPU |
| Cold prior | 0 | 0 | No currently eligible sample |
| History-informed prior | −.0625 | 0 | One matching native G3 prior for offer0 |

Hard-ineligible or unavailable branches are removed before the weight denominator. Unknown required evidence remains visible. Tampered or unverified prior is a failure; it cannot be silently replaced by a cold zero. Permitted ABSENT, EXPIRED or NONMATCHING history has value zero. Exploration `ρ = 0`; the mandatory reservation is not an exploration lane.

For surviving branches, the quantized softmax is:

`wᵢ = RHE(W × exp((zᵢ − z_max)/tau_fp))`, with `W = 10¹²` and `tau_fp = 250,000,000`.

Both z and tau are fixed-point integers, so their ratio needs no extra Q. Exponentiation uses a local Decimal context with precision 80 and half-even rounding; it does not mutate ambient process precision. Subsequent redistribution uses integer weights and exact `Fraction` arithmetic. This is a deterministic finite approximation of exponential weights, not an exact transcendental computation or a probability model.

|---|---:|---:|---:|---:|

| Integer weight | 1,000,000,000,000 | 985,111,939,603 | 983,881,318,977 | 1,000,000,000,000 |

The task budget has exactly nine dispatch units:

| Position | Count | Work |
|---|---:|---|
| Already spent | 1 | Mandatory `initial_constraint` |
| Available optional | 7 | Admitted offer checks |
| Still reserved | 1 | Mandatory final strategy consumer |
| Original total | **9** | `ONE_NATIVE_WORK_DISPATCH_UNIT` |

`A = total − spent − reserved_mandatory = 9 − 1 − 1 = 7`. The initial check is already in spent and is not subtracted twice. The final consumer's actual Work ID is `final_strategy`; configuration calls its mandatory role `final_strategy_consumer`. Each branch has lower quota 2 and upper quota 6. One unit means one admitted native Work dispatch, not CPU seconds, tokens, money or FLOPs. Mathematical evaluation and validation are not invented additional Host units.

The allocator starts at lower bounds and sets `T = min(A, Σ upper)`. It distributes `T − Σ lower` proportionally to positive integer weights using exact rational shares. All branches whose tentative share reaches their remaining capacity are saturated together; the remaining resource is redistributed among the others. Final extras are floored; residual units go to the largest fractional remainders, with stable branch-ID ties and caps respected. Thus every allocation respects its bounds, `Σ allocation = T ≤ A`, and `spent + reserved + Σ allocation ≤ total`. Any remainder `A − T` stays unallocated.

Negative available budget produces `BUDGET_INSUFFICIENT`; missing pressure evidence produces `NEEDS_MORE_EVIDENCE`; minima exceeding available budget produce `INFEASIBLE_MINIMA`. Refusals do not install partial success plans. Empty surviving sets preserve the remaining optional budget and mandatory obligations.
