## A01 / Another author built a working domain without acquiring admission authority

Gate 5 asks whether Radiolaria's way of constructing governed work can be transferred to a developer who did not build its core. The accepted example is a football booking domain written by an external model author. It computes offers from a synthetic venue's inventory, exchanges the result between two independent owners, performs a separately authorized mock booking and preserves verifiable history. The authoring result connects the Football and External DRS views: the program that performs those tasks has an inspectable construction history of its own.

The engineering basis of this dossier is commit 64f2b38b0d671e4907bae8649fff8f3d2ee0751c. Functional acceptance followed an explicitly amended authoring protocol: an initial submission and three corrections remained INCOMPLETE; one separately authorized fourth correction completed the technical acceptance. The final program was then reviewed and admitted through a different owner process. A successful submission did not install itself.

Here, Root means the local authority that decides for its own system. Work is the native unit of computation; Host and Firewall bind permitted execution and effects. The author received mechanisms for connecting a domain to these interfaces, not the power to overrule them. This is a finite transfer result for a reviewed Python reference profile. It supports the architectural interpretation that construction knowledge can travel while admission authority stays with the receiving owner. It does not establish unrestricted automatic software creation or an integrated synthesis factory.

## A02 / HOW specifies construction; WHAT specifies the football task

The public kit separates architecture from the requested application. HOW_TO_BUILD describes native Work, local Root review, pointer-first DRS retrieval, source provenance, currentness and effect admission. Its machine interface map gives exact callable signatures, fields, file locations and hashes extracted from the supplied source. The approved snapshot is a read-only interface reference. It is not a second editable kernel or a permission to use every function found in that snapshot.

The generic numerical example computes 3 × x + 2, giving 23 for input 7 and 35 for input 11. A distinct two-record MOCK example demonstrates bounded effect and receipt behavior. Neither example supplies a pitch-selection algorithm. The separate WHAT_TO_BUILD brief introduces the football conditions, finite inventory, half-open intervals, integer prices, explicit consent, deterministic preference order and evidence obligations. Knowing that a natural full-size field and ninety-minute sessions are required is ordinary task disclosure; handing over a winning set of slots would be a different intervention.

The football evidence fields are explicitly labeled as a task-specific profile in CANDIDATE_OUTPUT and FOOTBALL_PROFILE. Their names are not universal Radiolaria primitives. The shared E → B → C contract explains how an original computed result becomes published evidence and then verified consumption context. A future author can reuse that construction contract with another supported WHAT, subject to independent review. The kit therefore teaches a bounded method with concrete interfaces, rather than promising any program from an unconstrained natural-language instruction.

## A03 / The broker exposed seven bounded tools; execution belonged to the reviewer

The recorded author used gpt-6-astra with literal ultra effort and the default service tier. Its seven advertised broker tools could read or search approved sources, read candidate files, write or patch candidate text, inspect syntax as data and freeze a submission. A patch required the expected whole-file SHA-256 and a unique literal replacement. Submission caused the broker to calculate the package manifest. These operations provide a concrete account of what the author could see and change.

Source review and execution were separate stages. The supervisor read the initial candidate and every production change before approving a bounded runner invocation. The trusted parent created publisher and requester processes, assigned their role-specific inputs and channels, and recorded process results. The private examiner used independent source inputs and observations, rather than treating candidate-authored counters as an oracle. Later repository admission was another operation owned outside the candidate.

The white-room description is a metaphor for this declared access surface. It does not claim absence of pretraining, all platform context or all prior knowledge. The author broker is not a universal sandbox for arbitrary hostile Python. The reviewed-reference trust base includes the interpreter, approved source, runner, observer, independently frozen inputs and examiner. Same-process observation and shared worker UID are declared limitations. The earlier standalone command/exec canary discrepancy remains historical evidence; success through the narrower broker did not retroactively repair that different route.

## A05 / The earlier contract failure tested the instructions as well as the candidate

G54B1 revealed an important distinction between a computation and the evidence later built around it. E is the producer Work's actual result. B publishes that result together with the identity of the completed Work and its later review. C adds the receiving side's validated status and request context. They belong to one causal history, but they cannot be identical files: the original computation cannot contain identifiers of consequences that do not yet exist.

The old examiner required the whole published body at both Work boundaries while the public instruction required that body to be assembled after producer Work and review. The revised general contract checks the causal joins instead: payload_projection(B) equals E; source and review references resolve to actual evidence; expected C is independently derived from the signed body, current authenticated status, original request and local policy. The consumer's own input cannot be recycled as the expected input, since that would merely compare a claim with itself.

The correction was expressed generically and exercised with a numerical profile before the next cold author. The final football profile makes its mapping explicit: B.offer equals E, C.body equals B, and the consumer receives canonical C. This is an informative limit of instruction transfer. An independent author can expose a defect in the demanded proof as well as in its own implementation. The historical B1 failure remains recorded; a versioned repair to the shared contract supports the later success. Frozen examination is valuable because changes are visible, not because an examiner is assumed infallible.

## A12 / The published kit is a starting contract for another reviewed extension

A developer should begin with the current kit entry, then read HOW_TO_BUILD, SHARED_EVIDENCE_CONTRACT and the machine interface map. SOURCE_INVENTORY identifies the supplied code and schema resource; CANDIDATE_OUTPUT describes the bounded return package. The separate WHAT_TO_BUILD and FOOTBALL_PROFILE are the demonstrated application. The accepted football pack is useful as a disclosed example, but it must not be silently included in a future blind-author input. The auditor's historical corpus and private examiner are different deliverables.

A concrete extension point is the exact run_peer_v01 interface: role, input_data, state_root, output_root, channel and bootstrap are keyword arguments supplied by the approved runner. A reviewed local body profile supplies closed body/scope fields and local validate_body, validate_pointer and validate_binding functions. Neither a remote payload nor a signature selects executable code. A new implementation needs its own source review, supported runner and separate admission; this publication conveys construction knowledge, not the original owner's credentials or installation authority.

The observed transfer result is one new working domain created through this bounded contract. The architectural interpretation is that an extension's meaning and implementation can change while the receiving system retains the decision boundaries that govern use. Reflective Improvement Radiolaria, Cross-Domain Transfer Radiolaria and an integrated Capability Synthesis Factory are future directions, explicitly deferred beyond this reference. They may build on the same separation of proposals and decisions, but they are not implemented merely because a model successfully authored this package.
