## 2. Local responsibility and the whole monitoring task

The task is not to have a chatbot announce a landslide. It is to keep a bounded local monitoring process coherent across changed evidence and optional dependencies. A synthetic slope supplies rainfall, displacement and an independent reserve channel. The site coordinates a finite catalogue of diagnostic operations and monitoring actions. It can ask an analyst which investigation would resolve the present uncertainty, but that response does not set thresholds, invoke an arbitrary sensor, modify the Host or authorize a signal. The chronological S0-S5 story exercises configuration, changed rainfall, roles, outage and signal, queued report delivery, measured recovery and local semantic memory. Separate latest live experiments establish real semantic producer-to-consumer relationships that the controlled whole story does not claim to demonstrate.

The architecture separates a semantic role from the physical engine that supplies its contribution. A local algorithm, a future local SLM or a cloud model can fill a permitted role with truthful provenance. Sentinel uses common semantic-work DTOs and trust profiles to validate a contribution, common BSEP/router boundaries for current meaning, actual Work execution and independent Root review. Root is neither the Gemini response nor the deterministic diagnostic function. A Root acceptance of information does not automatically create permission. When an effect is needed, a separate current action packet, live Host state and admitted capability validation are required. The point is local responsibility with replaceable reasoning, not a claim that the demonstrated software is a certified landslide-warning system.

The local Root identity persists across the relevant episode. A fresh invocation may be created for new work without manufacturing a second effect owner or resetting an existing task's spending. The domain adapter supplies a finite interpretation of observations and commands. It does not replace the shared semantic-work validator, execution-mode router, D/E runtime, Work materializer, Root decision kernel or effect firewall.

This distinction makes an edge deployment coherent: the cell can continue a bounded local responsibility even if a useful external analyst is unavailable. The current demonstration uses synthetic local observations and mock effect adapters. It shows that the program structure can maintain those boundaries; deployment still needs the physical and operational contracts appropriate to actual equipment.

## 5. Duty-specific context and the model interface

semantic_adapter_v01.context filters channels by intended duty. Local slope and adversarial duties receive displacement and reserve observations plus the maintenance note. The environmental duty receives rainfall and omits that local note. Source records include identity, time, unit, calibration and lineage as applicable. The supplied context states the synthetic origin and the channels not included. It supplies duty-specific investigation contracts: target, intended use, required evidence, bounded result classes and limits. The model is asked to select a useful investigation, not to choose an outcome. Provider requests are captured privately with exact context digests. This is a finite semantic boundary, not a claim that the LLM never sees domain measurements or that all context is cryptographically secret.

The exact allowed response has diagnostic, source_refs and reason. validate_response checks a closed dictionary shape, an allowed diagnostic for this duty, a nonempty unique set of references belonging to supplied sources, and a bounded nonempty reason. Gemini uses a structured response schema, but the local validator remains the actual consumer-side check. Source references are citations: they cannot suppress compulsory companion observations, trigger a new acquisition, select arbitrary endpoints, change cadence, edit policy or provide a permission token. The runtime creates ActorContributionV01 with actual contribution_mode CLOUD_LLM and actor_role provider_llm, checks it against the semantic request and default trust profiles, and builds a review packet. Intended local role and actual cloud origin remain separate fields.

The provider response schema is closed:

```json
{
  "diagnostic": "ONE_ALLOWED_DIAGNOSTIC",
  "source_refs": ["KNOWN_SUPPLIED_SOURCE_ID"],
  "reason": "A bounded reason for the proposed investigation"
}
```

This example is a schema illustration, not a captured provider response. The actual allowed diagnostic enum depends on the duty. Local and adversarial duties can select `REFERENCE_INTEGRITY`, `INDEPENDENT_RESERVE_SERIES` or `EVIDENCE_GAPS`; the environmental duty can select `TEMPORAL_CONTEXT_APPLICABILITY`, `SPATIAL_CONTEXT_APPLICABILITY` or `EVIDENCE_GAPS`. The runtime checks the returned shape and values even though the provider is also asked for structured JSON.

The role context's `source_refs` meaning is explicitly `CITATIONS_NOT_ACQUISITION_OR_OPTIONAL_SAFETY_FILTERS`. Compulsory companion observations remain in the material whether or not the model cites them. A returned citation therefore cannot remove an unfavorable local witness or authorize a network read. The runtime, rather than the model, chooses the current acquisition boundary when the accepted investigation actually requires one.

## 14. Measured recovery, current policy and distinct OFF

The finite synthetic incident policy requires both displacement and reserve below or equal to 1000 micrometres, at least three new independent pairs, measured coverage of at least 30 seconds on each channel and no gap above 15 seconds. Current policy controls admissible local age. In LS2R2, a policy allowing age two seconds actually rejects five-second-old data; fresh witnesses can then establish valid recovery. Tests cover boundary values two, ten and twelve. Witnesses from changed calibration, lineage, units, statistic or relevant policy cannot be combined with earlier coverage: old witness history is retained as revoked evidence. Receipt timing and repeated old IDs cannot create a recovery interval. Even clearance remains a candidate condition until an independent current Root decision and native OFF complete.

`Incident.evaluate` calls the module-level `features` function, which passes the current age limit through `local_pair` into `EventBook.current`, rather than accepting a policy value and ignoring it in the recovery path. The corrected tests discriminate an accepted age of two seconds from the old fixed ten-second behavior. Fresh data at the permitted boundary can support recovery; stale data beyond that policy cannot.

Recovery coverage is keyed by relevant source and policy facts: site, channel, lineage, calibration, unit, statistic, recovery policy and the current critical/age parameters. Observation IDs themselves do not become the stable dependency fingerprint; new compatible samples must be allowed to accumulate. A change of stable dependencies revokes old coverage while retaining it as historical evidence. Repeated old IDs, nonadvancing measured intervals and excessive gaps do not accumulate the required duration.

The resulting `clearance` condition is not the OFF effect. The local coordinator still performs a normal current decision and native dispatch, and only the resulting receipt closes the incident. Cleanup, late LLM text, a recovered network or a delivered report has no equivalent authority.

## 15. Immutable outbox and acknowledged delivery

The local mock outbox creates an immutable report payload, message identity and payload digest. Delivery attempts preserve those exact bytes, and the receiver acknowledgement must match the same identity and hash. The retained story records QUEUED, ATTEMPTED and RECEIVED. Negative controls cover a missing acknowledgement, changed payload, receipt misuse and expired action packets. A receipt is evidence of a prior bounded action; it is not authority to send again. This demonstrates a local source-bound report protocol and exact acknowledgement semantics. It does not claim distributed exactly-once delivery over arbitrary networks or that a public emergency authority received an alert. Network recovery does not clear the incident; recovery/OFF is a separate local path.

The report's payload identity is derived from its exact bytes. A receiver must acknowledge the same message and payload hash. Queue state and delivery state are therefore separate from the incident's safety state. A lost acknowledgement leaves an explicitly uncertain outcome instead of a made-up success. This local protocol can be inspected in `outbox_v01.py` and the historical C09 records.

The package preserves failed or refused operations as evidence. It does not equate a previously recorded receipt with a fresh permission to invoke an effect. Distributed exactly-once delivery, durable transport across arbitrary failures and external agency acknowledgement are beyond this local mock demonstration.
