Four Evidence-Bound Contributions

  1. CL01 Compose useful activity without giving proposals authority
  2. CL02 Use another owner's computed result without importing its permission
  3. CL03 Keep history useful while rechecking current use
  4. CL04 Admit externally authored programs through an independent boundary

CL01 Compose useful activity without giving proposals authority

Type: ARCHITECTURAL_INFERENCE

Practical Change: An application can combine semantic interpretation, typed code and services while keeping acceptance local.

Mechanism: Runtime materializes topology; Work returns evidence; each Root accepts independently; a current packet precedes Firewall dispatch.

Sources: specs/current_architecture_lock_v01.md; docs/gate6_reference_v01/contract_index.json

Verification: Read accepted architecture and the finite source/contract map. No universal execution guarantee.

Evidence Type: Accepted contract plus recorded reference implementations

Limitation: An integrator must supply valid profiles, source bindings and bounded effect adapters; this is not a bootable host OS.

CL02 Use another owner's computed result without importing its permission

Type: INDEPENDENT_CHECK

Practical Change: A venue offer becomes an actual input to a different owner's Work.

Mechanism: E is wrapped in B after local review; a release and current STATUS bind received bytes; C becomes requester offer_json.

Sources: main_pub_shift_venue_work; main_pub_shift_offer_body; main_req_shift_requester_work; main_trusted_parent_receipt

Verification: Read episode and QA joins; compare full recorded objects by hashes.

Evidence Type: Fresh data-only joins of historical G54D1

Limitation: Reviewed observer/reference code are trusted. This is not cryptographic remote execution attestation or a fresh signature replay.

CL03 Keep history useful while rechecking current use

Type: OBSERVED_EXECUTION

Practical Change: Repeated or verified booking history need not cause another effect; revoked data does not become usable because it was signed.

Mechanism: Local history and current status are different predicates; REVOKED fails before consumer Work; separate BOOK consent owns the effect.

Sources: main_req_repeat_history; main_req_verify_history; negative_shift_status; negative_shift_refusal_review; main_trusted_parent_receipt

Verification: Compare event counts, readback and the negative Root reason in the episode.

Evidence Type: Recorded native outcomes with new finite consistency checks

Limitation: Counts are observed operations, not a general wall-time speedup. A current use beyond the recorded window requires a new check.

CL04 Admit externally authored programs through an independent boundary

Type: OBSERVED_EXECUTION

Practical Change: Domain code can be authored outside the kernel and examined against public interfaces and a separate oracle.

Mechanism: HOW plus WHAT produces a candidate; independent reference execution and source review precede admission.

Sources: docs/gate5_authoring_kit_v01/START_HERE.md; docs/showcase/gate5_reference_v01/dossiers/A.md; docs/gate6_reference_v01/FINITE_COMPLETION.md

Verification: Follow the historical G54D1 lineage and accepted source binding. Do not run recovered helpers.

Evidence Type: Retained accepted reference evidence

Limitation: G54B1 and G54D remain INCOMPLETE; G54D1 used authorized correction 4 in restored continuation. Not a one-shot success or arbitrary-code isolation.
