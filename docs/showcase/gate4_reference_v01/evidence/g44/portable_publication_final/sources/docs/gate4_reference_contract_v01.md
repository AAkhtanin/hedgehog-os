## Probe Contract

The controlled profile creates a new source snapshot from existing Airline
record types, never modifies old oracles. It uses the fixed transaction scope
of that existing Airline contract, with new offer/source/task/occurrence IDs;
this is not a claim of arbitrary transaction support. Two pure check definitions
are admitted through the existing public local path. Actual enrolled Work and
Root consumption are the probe, not AVF-derived adaptive allocation.

Mandatory pure quanta are constraint and provenance validation. The final Root
consumer is an ordinary decision, not a capability dispatch: zero native compute
units and separately measured time. No future allocator may omit a genuine
consumer dispatch from M. No provider, action packet, booking or payment occurs.
Current/stale snapshots and terminal retry use native ledger APIs. Full native
G3 history write/query/descent is mapped, not executed. The native proof profile
may admit multiple completed Work rows; the predictive profile additionally
requires a single result row. These distinct contracts must not be conflated.
